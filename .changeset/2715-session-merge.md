The session runner now merges an approved, green pull request itself and carries on, instead of stopping for you. Each merge goes through the fleet's own checks: the current reviewer's approval at the exact head, the overload guard, then `merge.py`, through the merge queue where there is one. While builders or reviewers still run, it keeps polling CI and the merge queue, so a pull request that turns green merges at once. It waits for a reviewer that is still finishing, and records `merge blocked` on the pull request when the approval can't be tied to the current reviewer. Where the project configures overload state (`LAUNCH_FLEET_OVERLOAD_STATE`) or an overload supplier (`LAUNCH_FLEET_OVERLOAD_SUPPLY`), each merge batch passes the fleet's overload guard on that shared state (stopping before merging when a supplier or input is set without `LAUNCH_FLEET_OVERLOAD_STATE`); a genuinely fresh project with none of those configured merges without the overload guard.
