# Approval, frontier and claim gate

Moved from `SKILL.md`'s Approval guard; read when a start is refused, clashes, or needs reconciliation.

A ticket is on the **frontier** only when its spec's latest plan approval (to-tickets' complete machine plan approval, its table naming exactly its revision text and that text hashing to the current fingerprint, or an older one by the user) is current (to-tickets' `revision.sh` fingerprint matches), no comment on the spec's video holds or steers it ([steer.md](steer.md)), it is open with only the ready label, every **hard blocker** has a **verified merge** (closed by a pull request merged into the default branch), its owned paths don't collide with a running ticket's, and it has no builder, open pull request or hold. A native blocker is context and holds nothing (F6) only when to-tickets' `check-links.sh` reads its one line as a `file` line naming a file, the blocker's owned paths are read, neither those paths nor the line's files hold an input the ticket relies on, and the two tickets' owned paths don't clash; anything else is hard. Owned paths are read and matched as to-tickets' `approve.py` reads them (fnmatch patterns); two clash when they overlap in one repository and not both bullets say `(shared`. The start set is admitted in number order, each against running work and those admitted before it. The claim is the gate every builder start passes. It finds the repository's running work whatever its labels, so a ticket held by hand still counts: it reads every open issue that has the ready label, a `launch-fleet` record in its comments or a linked pull request, and fails the read when a search lists fewer than it counts. Being found is not running: a found ticket counts as running only with a live builder record from a record author (`launch-fleet: started` or `launch-fleet: start checked, branch <b>`) or an open pull request linked to close it. Any other `launch-fleet` record, such as a hold or a note, makes it found and stops nothing. The claim withdraws a start whose owned paths clash with a found ticket that is running, claimed by an older `launch-fleet: starting` claim, or whose start history can't be read in full. A legacy `take over` start reads the same three sources and holds on a clash with any running or claimed ticket, or one whose history can't be read. Work with no live builder record and no open linked pull request (a builder started outside the fleet, or one whose records were removed) can't stop a clashing start, whatever else its ticket carries: before the fleet starts on those paths, have a record author post its `launch-fleet: started` record, or open its pull request linked to close the ticket. A started ticket's newest ready labelling must be a maintainer's (a record author, or write access) with no edit to the ticket since; otherwise the check prints one `look #N: start refused: ...` saying a maintainer must add the label again (#1448).
