# Records and private routing

Read this when changing private routing or running the check's other commands. SKILL.md's "Records" table holds every record form. `scripts/post.py` writes every record and refuses private identities.

## Records

The loop's memory: comments on GitHub, each starting `launch-fleet:`. Edit a claim as its start moves on; a retry is a new comment.

| On | Record | Means |
| --- | --- | --- |
| A ticket | `launch-fleet: starting` | A start is claimed |
| | `launch-fleet: started` | Its builder started |
| | `launch-fleet: builder fallback due, branch <branch>` | The single builder fallback is reserved |
| | `launch-fleet: start checked, branch <branch>` | Thread, ticket and branch checked |
| | `launch-fleet: start refused: <reason>` / `start not tried: <why>` / `start failed: <why>` / `start withdrawn` | No builder: it stays on the frontier (a refused or untried start after 10 minutes) |
| | `launch-fleet: held for ordering: issue #B merges to main` / `held for ordering: PR #P merges to main` | An owned ordering-only hold, after its label change |
| | `launch-fleet: held manual: <why>` / `held live: <why>` | A manual/live gate, even while already labelled held; its owner supplies separate release evidence |
| | `launch-fleet: release starting <hold comment id>` / `released ordering C` / `release failed C: <why>` / `release withdrawn C` | A release intent and its verified outcome; unresolved intents block starts |
| | `launch-fleet: held for #<P>` / `noted #<P>` | An existing contract hold, or a builder told of a change |
| | `launch-fleet: asked the orchestrator` | Its `needs-info` question was passed on |
| | `launch-fleet: granted <kind>: <reason>` / `granted spec change on #<S>: <reason>` | The fleet granted itself one of F4's four kinds; it answers the question |
| | `launch-fleet: told the user` | A person's ticket is ready, and the user knows |
| | `launch-fleet: complete: <evidence>` | The orchestrator or owning fleet thread records a person's completed work and names its evidence; with the ticket closed, its dependents may start |
| | `launch-fleet: waiting for #<B>` / `resume starting <wait comment id> for #<B>` / `resume sent <wait comment id> for #<B>` / `resume failed <wait comment id> for #<B>: <why>` / `resume withdrawn <wait comment id> for #<B>` | The builder waits for a verified merge, or was told to resume that wait |
| | `launch-fleet: archived` | Its builder and reviewer are archived |
| | `launch-fleet: old builder archived, start <start comment id>` | The orchestrator archived that builder, from before the spec's fleet thread, so the fleet thread may start its own (a takeover) |
| A pull request | `launch-fleet: review starting <commit>` / `review started <commit>` / `review refused <commit>: <reason>` / `review failed <commit>: <why>` / `review withdrawn <commit>` | Its reviewer for that commit |
| | `launch-fleet: re-check sent <commit>` | The same reviewer asked to re-check |
| | `launch-fleet: review told again <commit>` / `review given up <commit>: <why>` | A quiet reviewer was told again, or given up on (its thread archived) |
| | `launch-fleet: CI failure sent <commit>` / `findings sent <commit>` | The builder was told |
| | `launch-fleet: merge queued <commit>: <what allowed it>` | It waits in the merge queue at that commit |
| | `launch-fleet: re-test starting <commit>` / `re-test sent <commit> on <base> in run <run id>: <what main changed>` / `re-test failed <commit>: <why>` | Its CI was started again at that head, and the `main` it tested (the re-test guard) |
| | `launch-fleet: merge main asked <commit>` | Its builder was told to merge `main` in, as its re-test ran on an old `main` |
| | `launch-fleet: merge dropped <commit>: <reason> at <time>` | The merge queue dropped it at that head, for GitHub's reason; one automatic re-queue per head once the cause is gone, claimed first by `launch-fleet: merge re-queue claimed <commit>: <reason> at <time>` (the earliest claim counts, and a claimed re-queue is never tried again) |
| | `launch-fleet: merge blocked <commit>: <why>` | The merge waits for someone |
| A spec | `launch-fleet: needs approval: <what changed>` / `spec summary` | The user was asked, or told it is done |
| | `launch-fleet: spec changed for #<N>: <reason>` | A truly necessary spec change the fleet granted itself for that ticket |
| | `launch-fleet: late look asked #<P> at <commit>` | The evidence ask: the final merge of a user-visible spec waits for the owner's late look at that head ([references/reviews.md](reviews.md), "The late look") |
| | `launch-fleet: fleet active, loop fleet-<S>` | The spec's loop's public handle (the real loop id stays under `S` in the private loop file). The latest counts. A separate `Wake mode: fresh` line keeps existing assignments across wakes |
| | `launch-fleet: look: live check not recorded as passed` / `live check passed` | Evidence is missing (one alert), or a newer explicit pass has been verified and the wait is released; the pass line may append `: <evidence source>` |
| | `launch-fleet: look: live check evidence to verify in comment <id>` | The tick inspected that new evidence comment without establishing the required pass; do not repeat its verification task |
| A run's commit | `launch-fleet: nightly telling <run> attempt <attempt>` / `nightly told <run> attempt <attempt>` / `nightly uncertain <run> attempt <attempt>` | Notification claimed, delivered, or settled after one uncertainty notice |
| Any of them | `launch-fleet: look: <the line's reason>` | Someone was asked to look |

## Public records and private routing

Follow `contracts/open-development.v1.md`, Fleet records. Every GitHub write, on either repository, uses the public form. Never put a thread id in a comment, report, reason or helper log. Due lines and CloudRoom commands are private routing inputs: do not copy their identities into public `look` or failure reasons. Name the ticket, pull request, commit, branch or claim comment instead. Check every proposed public body for thread ids before posting; if its reason contains one, replace the reason with a plain description tied to those public facts.

`scripts/records.py` resolves builders by the exact `#<N>: ` title prefix and the checked branch, excluding helpers. Reviewers match `Review #<P> at <short start commit>`, and a reviewer of another repository's pull request matches only `Review <OWNER>/<NAME>#<P> at <short start commit>` (case-insensitive), so discovery never gives it this repository's same-numbered reviewer (#1977). Order records by comment creation: each `review started <A>` opens a span until the next start. Re-checks, told-again and give-up records at any later commit belong to that original reviewer. Giving up closes the whole span, even if its claim was edited in place and later told-again records remain. Never contact a closed span; start a fresh reviewer or record a thread-free `look`. None or an unreadable source is out of reach; two matches or disagreement with private state is a `look`, never a guess. Today's forms are read only when repository privacy is positively known; unknown is public.

Before posting a successful start or delivery, save its identity in private state, outside the public checkout (or `private/orchestration/` in the private repository). Set `LAUNCH_FLEET_STATE` to that absolute JSON file. Its shape is `{"repo":"owner/name","threads":{"builder:N":"<thread>","review:P:FULL_START_COMMIT":"<thread>","review:P:claim:CLAIM_COMMENT_ID":"<thread>","comment:CLAIM_COMMENT_ID":"<sender>","fleet:S":"<fleet>"}}`. It holds thread identities only. `P` is the pull request's bare number when it is in this repository, and `OWNER/NAME#P` when it is in another one (`review:other-owner/other-repo#58:FULL_START_COMMIT`), so it never shares a key with this repository's same-numbered item (#1977); `scripts/records.py` reads that repository from the key, case-insensitively, and reads the bare form only for this repository's pull requests. Driver runs (#1371) go in a third private file beside it, `LAUNCH_FLEET_RUNS`, shaped `{"repo":"owner/name","runs":{"N":{"host":"<name>","run":"<run id>"}}}` and written only by `scripts/host.py`; restore it with the others on every wake and save it back after each start or stop. Loop ids go in a separate private file beside it, never in this map: set `LAUNCH_FLEET_LOOPS` to that absolute JSON file, shaped `{"repo":"owner/name","loops":{"S":"<loop id>"}}`; no check reads it, only the agent resolving a handle. Save each claim's sender before sending; a re-check adds its commit key to the same reviewer. Before editing a review-start claim to success, save its immutable `review:P:claim:CLAIM_COMMENT_ID` key as well. Give-up retires every routing key for that reviewer, but keeps that claim mapping for archive-only cleanup at ticket closure. Never overwrite or delete a retired claim mapping: a replacement, even at the same commit, gets a new claim key. Commit aliases may change; they cannot replace the retained claim identity. The reader never changes this map. Do not guess a sender for an unresolved resume, release or nightly claim: without private evidence proving delivery or non-delivery, leave it claimed and ask the orchestrator. A safety-net sandbox without CloudRoom can use this private map; without either source it reports out of reach, and the agent tick resolves the public facts in its own CloudRoom context.

After a verified merge with no project cost command, `merge.py cost` reads the ticket's `builder:<N>` and the pull request's `review:<P>:...` threads from `LAUNCH_FLEET_STATE`, the ticket's own fleet's state even when the pull request is in another repository, with `room-cli usage <thread> --json` and posts their `history.credits` as `launch-fleet: cost: Ticket #<N> cost (PR #<P>): builder <x> credits, unknown tokens; reviewer <y> credits, unknown tokens; CI unknown; total <x+y> credits, unknown tokens, unknown runner minutes`, with `(PR <owner>/<repo>#<P>)` for a pull request in another repository, every reviewer summed and no thread id. No state, a missing agent, a driver-started builder or reviewer (a `run:` key or a run-map entry for the ticket or the pull request), a failed or malformed read, or a read whose first hour is the 7-day window's first hour makes that role `unknown`, and any unknown role makes the total `unknown`, never zero.

An old-builder archive records `launch-fleet: old builder archived, start <start comment id>` for legacy takeovers. The spec's loop is advertised as `launch-fleet: fleet active, loop fleet-<S>`. A separate line `Wake mode: fresh` in that same comment marks a loop that starts fresh threads. The real loop id stays under `S` in the private loop file. No wake writes its own identity as the fleet's identity.

## The check

`scripts/fleet.sh`, beside this file, is the loop's check, the tick's read of what it was woken for, and the frontier and contract-note helpers. It only reads, through `gh` and `jq`. For a spec with a ticket that could start, it runs `to-tickets`'s `revision.sh` (in `skills/to-tickets/`) to check the approval is current. `scripts/loop.sh` is the safety net's script, which runs it, and with `FLEET_SPEC` set, a fleet thread's loop's script, which runs `spec <S>`.

| Command | Prints |
| --- | --- |
| `sh "<this skill's folder>/scripts/fleet.sh"` | Every due line, or nothing when nothing is due (exit 0) |
| `sh "<this skill's folder>/scripts/fleet.sh" wake <N>...` | The due lines about issues and pull requests `<N>...` alone, read alone: a pull request with every ticket it closes, a ticket with its spec's approval (its whole spec, when it could start), an issue approved on its own, a spec in full. A number that is no issue or pull request is nothing. Lines on anything else wait for the check, and so do a spec's own lines (`re-approve`, `spec done`, `close spec`) unless the wake names the spec; for a spec with a fleet thread, only its `wake fleet` line |
| `sh "<this skill's folder>/scripts/fleet.sh" spec <S>` | The due lines of spec `<S>` alone; `fleet done #<S>` when `<S>` is no open spec. Legacy fleet records can still produce takeover lines. The full check prints nothing about a spec with a fleet thread, and `wake` prints only its `wake fleet` line |
| `sh "<this skill's folder>/scripts/fleet.sh" every` | The check's lines on every spec, fleet threads' too, and on the issues approved on their own: a fleet thread's read before a merge |
| `sh "<this skill's folder>/scripts/fleet.sh" frontier` | Every ticket that may start now |
| `sh "<this skill's folder>/scripts/fleet.sh" holds` | Every contract change note due for a builder (legacy command name) |
| `sh "<this skill's folder>/scripts/fleet.sh" claim <N> <comment id>` | After a claim on ticket or pull request `<N>`: `go #<N>`, or `withdraw #<N>: <why>`. It reads only `<N>`, as `wake` does |

It exits 2, with the reason, when it can't read what it needs. Its tests run on synthetic GitHub answers: `sh "<this skill's folder>/scripts/test.sh"`.

`scripts/route.py` is the wake route's two lookups (FF2, #1332), with `GH_REPO` the project: `route.py refs <owner>/<repo> <N>...` prints the project's tickets that messages from that repository name (its own numbers unchanged; another repository's pull requests give the project issues they close, in one GraphQL read), and `route.py loop <loop map> <S>` prints the loop id under `S`, or nothing, exit 0, when the map, key or id is missing or unusable. `route.py tick <owner>/<repo> <loop map> <N>...` is a webhook tick's whole read for one repository's messages: those two lookups around `fleet.sh wake`, which it runs only when the group names a ticket, printing `wake fleet #<S>: room-cli loop run <loop id>` or `wake fleet #<S>: unresolved` and every other wake line unchanged. It exits 2 on bad arguments or a failed or partial read. Tests: `python3 -I "<this skill's folder>/scripts/test-route.py"`.

## Conditional reads

Every repeated REST poll from Python goes through `scripts/ghcache.py` (FR7, openwizdev/OpenWiz#2624), so an unchanged answer is a `304` that costs no primary allowance; `fleet.sh` keeps its own `rest` cache. `ghcache.get(endpoint, accept=None)` returns one parsed answer and `ghcache.pages(endpoint)` every page of a list, following `Link`; from a shell, `python3 -I scripts/ghcache.py get ENDPOINT [--accept MEDIA]` prints the answer. Each GET sends the saved ETag in `If-None-Match`; a `200` counts only when `gh` exits 0, and saves the new ETag, `Link` and body under `${XDG_CACHE_HOME:-~/.cache}/launch-fleet/rest/`, atomically and with one SHA-256 over all three, checked before the ETag is sent. A `304` that brings a fresh `Link` saves it for later `304`s that omit one; if that save fails, the read raises and drops the old entry, so the next read is a full `200`. Before creating anything, every folder from `/` down to the cache is opened without following symlinks and checked: each ancestor is owned by this user or root and not group- or other-writable unless sticky, and `launch-fleet/` and `rest/` are this user's and not group- or other-writable; `rest/` is kept owner-only (`0700`), and every entry read, write and removal goes through that one opened folder, so a later swap of any path above it changes nothing. An entry that is symlinked, foreign-owned or open to group or others is refused before use. A damaged entry (removed as it raises), an unsafe one, a `304` with no entry, a failed `gh` or any other status raises `ghcache.Error` (the CLI exits 1): treat it as a failed read, never an empty one. Errors name only the endpoint's path, never its query or a server-given host, and a fixed label when the endpoint can't be parsed. It only reads; writes go through their own writers. Tests: `python3 -I "<this skill's folder>/scripts/test-ghcache.py"`.
