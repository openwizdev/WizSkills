# First run — 2026-11-01

This example comes from the first overnight run while the skill was being specified. Read it as the lessons that run taught, not as permission to repeat endpoint access or as proof this written procedure has run. Its records (commits, issue numbers, counts and outputs) stay in the private record; this page keeps no measurements from it, and its examples are described, not reproduced.

The confirmed grill settled the six rules: bedtime invocation; day review and hunting; reproduction before filing; Terra-wide/Sol-judgment/fixes plus research; reversible small fixes within exact paths; report near 9 am and continue until done. Its later confirmation supersedes the research's earlier “open” status.

## A reproduced documentation finding

The docs hunt inspected the project's documents on main and filed each reproduced finding as an issue with `overnight` and `needs-triage`, read back after filing. Each issue, rather than the hunt notes alone, holds its command and red output.

For example, one finding compared the orchestration guide's spawn example against the Cloud endpoint's actual `thread spawn --help`. The assertion failed because the documented flags were absent from that endpoint's usage. The failing comparison started no thread. It established a documentation mismatch, not a product-write failure, and the suggested repair stayed in the one document, through ordinary small-fix triage.

The same notes marked running-agent counts, loop status and machine state **suspected, not filed**, since they needed endpoint observations the hunt did not obtain. Installed-plugin compatibility also remained unverified. A clean local build did not upgrade those suspicions to facts.

## Sessions and review corrections

The sessions hunt collected GitHub comments, Actions runs and the finished builder and reviewer outputs that were available. It distinguished active snapshots from finished sessions and kept raw outputs outside Git. That access was specific to that hunt; this example supplies no new access approval.

Its findings were synthetic reproductions: a plugin consumer hitting repository-relative command failures, and an approval-table comparison showing a current fingerprint alone did not guarantee a launchable approval record. The fleet correctly failed closed. The proposed repair validated the posted approval record rather than weakening the start gate.

Repeated scope questions and policy concerns remained suspicions without an executable reproduction. Already-owned CI failures and review findings were linked instead of refiled. This is the deduplication and uncertainty boundary the skill preserves.

## Other reproduced first-run findings

The bug hunt filed findings from fake-backed CLI reproductions: missing fleet-to-agent wiring, and a legitimate no-check CLI response that fixtures represented incorrectly. It rejected a truncation suspicion after checking the source tool's actual pagination behaviour.

The skills and infra hunt filed an evidence check that used moving main as a historical baseline, and a controlled archive-to-FIFO swap that reproduced a cache-copy hang. A service crash-window concern stayed unfiled because it had no executable reproduction. Both hunts kept changes to evidence only and put complete failing reproducers on the issues. Their passing subsystem tests did not erase the independently reproduced failures.

## Research incorporated

The research cites primary sources and proposes improvements: a run contract; explicit session coverage; distinct hunt lanes; a candidate ledger; measured flake/docs evidence; routing by task/evidence; deduplication and claims; impact-based small-fix boundaries; durable progress and independent reporting; and a useful report with later evaluation.

The skill incorporates these as procedures, not measured performance claims. The research's suggested small initial rollout of hunters is not an approved cap and is not imposed. Its suggestion of Sol evaluation in a separate context preserves the project's required reviewer family and exact-head gate. Fixed trial limits, success scores and cost estimates from other projects are not imported.

Matt Pocock's `/repro` could not be verified at the inspected public tree. The research instead identifies public `retro`, `diagnosing-bugs` and other sources as related reading. Do not call this a `/repro` adaptation. Dream-cycle reports supply design ideas, not evidence of this repository's cost, quality or overnight success rate.
